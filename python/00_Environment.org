* pip

** WHAT

pip 是 Python 的包管理工具，用来装三方库和三方工具。

但 Arch 的 python 包不带 pip（pip 被单独拆成 python-pip），系统 Python 又标记为
externally-managed（PEP 668）。直接 pip install 会装进 /usr，和 pacman 的包重叠，
导致版本混乱、依赖冲突，甚至弄坏依赖 Python 的系统工具。

（本机现状：python 3.14.7，python-pip 未安装，`python3 -m pip` 会报 No module named pip。）

** HOW

别往系统里装：命令行工具用 pipx（见下），项目依赖用 venv / uv。
真要系统 pip：`sudo pacman -S python-pip`。

* pipx

** WHAT

pipx 是 Arch 社区广泛推荐的方案：
- 每个应用一个独立 venv，互不干扰
- 自动把可执行文件 link 到 PATH
- pipx upgrade / uninstall 好管理
- 不污染全局 Python 环境

定位：装命令行工具（ruff、pylsp…）；项目依赖别用 pipx。

** HOW

*** 安装

#+begin_src shell
sudo pacman -S python-pipx
pipx ensurepath          # 把 ~/.local/bin 写进 PATH
# sudo pipx ensurepath --global   # 全局安装时用
#+end_src

*** 镜像

path: $HOME/.config/pip/pip.conf

#+begin_src ini
[global]
index-url = https://pypi.tuna.tsinghua.edu.cn/simple/
#+end_src

pipx 内部也是用 pip 装的，会读这份全局配置，所以命令里通常不用再写 -i。

*** 命令

#+begin_src shell
pipx install 包            # pipx install ruff
pipx list                  # 看装了啥
pipx upgrade 包            # 升级单个
pipx upgrade-all           # 全部升级
pipx uninstall 包
pipx run 包                # 不安装，临时跑（写脚本时好用）
pipx runpip 包 pip install ...   # 在某个 venv 里跑 pip
#+end_src

* python-ts-mode + eglot

** WHAT

python-ts-mode 是 Emacs 29 起内置的 tree-sitter 模式，本机 Emacs 31.1，不用额外装。

** HOW

*** 语言服务器 pylsp

eglot（Emacs 内置）连 pylsp。两种装法，推荐 pacman——跟系统包统一，少一个 venv。

#+begin_src shell
# 推荐：pacman（本机已装，可执行文件在 /usr/bin/pylsp）
sudo pacman -S python-lsp-server

# 或者：pipx（隔离在自己的 venv 里）
pipx install python-lsp-server
#+end_src

** 格式化 / lint：ruff

#+begin_src shell
pipx install ruff
ruff format .      # 格式化
ruff check .       # lint
#+end_src

* uv

** WHAT

uv 是现在主流的 Python 包 / 项目管理器，一个工具顶 pip + pipx + venv + pyenv：

** HOW

*** 安装

#+begin_src shell
sudo pacman -S uv
uv venv                    # 建虚拟环境
uv pip install 包          # 装依赖
uv run python xxx.py       # 在环境里跑
uv tool install ruff       # 相当于 pipx install
#+end_src
