* Environment

环境笔记的格式是**决策 + 操作手册**（结论 / 为什么 / 命令 / 现状），不是概念笔记。
判据和全局一致：**删掉定义，保留本机处境**。

** pip

*** 结论

不要用系统 pip。命令行工具走 pipx（见下），项目依赖走 uv / venv。
真要系统 pip：~sudo pacman -S python-pip~。

*** 为什么

Arch 的 python 包不带 pip（pip 被单独拆成 ~python-pip~），系统 Python 又标记为
externally-managed（PEP 668）。直接 ~pip install~ 会装进 ~/usr~，和 pacman 的包重叠，
导致版本混乱、依赖冲突，甚至弄坏依赖 Python 的系统工具。

*** 现状

python 3.14.7；~python-pip~ 未安装；~python3 -m pip~ 报 No module named pip。
再确认：~pacman -Q python-pip~

** pipx

*** 结论

装**命令行工具**用它（ruff、pylsp…）。项目依赖别用。

*** 为什么

每个应用一个独立 venv，互不干扰；可执行文件自动 link 到 PATH；
~upgrade~ / ~uninstall~ 好管理；不污染全局 Python 环境。

*** 命令

安装：

#+begin_src shell
sudo pacman -S python-pipx
pipx ensurepath          # 把 ~/.local/bin 写进 PATH
# sudo pipx ensurepath --global   # 全局安装时用
#+end_src

镜像（path: ~$HOME/.config/pip/pip.conf~）：

#+begin_src ini
[global]
index-url = https://pypi.tuna.tsinghua.edu.cn/simple/
#+end_src

pipx 内部也是用 pip 装的，会读这份全局配置，所以命令里通常不用再写 ~-i~。

常用：

#+begin_src shell
pipx install 包            # pipx install ruff
pipx list                  # 看装了啥
pipx upgrade 包            # 升级单个
pipx upgrade-all           # 全部升级
pipx uninstall 包
pipx run 包                # 不安装，临时跑（写脚本时好用）
pipx runpip 包 pip install ...   # 在某个 venv 里跑 pip
#+end_src

*** 现状

~python-pipx 1.15.0~ 已装；已装工具：ruff 0.16.10（pipx 装的）。
再确认：~pipx list~

** uv

*** 结论

项目环境优先用 uv（一个工具顶 pip + pipx + venv + pyenv）。用 pacman 装。
**不用配镜像**（见下）。

*** 为什么

- uv 官方明确**不读** pip 的配置（~pip.conf~ / ~PIP_INDEX_URL~），
  所以本机 pip 的清华源对 uv **无效**；uv 自己的配置在 ~$HOME/.config/uv/uv.toml~。
- 实测直连 ~download.pytorch.org~ 约 **7 MB/s**，torch 轮子 1–2 GB 几分钟下完，不值得折腾镜像。

*** 命令

安装：

#+begin_src shell
# 仓库包（extra）。装成 pacman 包后 uv self update 会拒绝自我更新，升级统一走 pacman -Syu
sudo pacman -S uv
#+end_src

建环境 + 装依赖：

#+begin_src shell
uv venv --python 3.14       # 建虚拟环境
uv pip install 包           # 装依赖
uv run python xxx.py        # 在环境里跑
uv tool install ruff        # 相当于 pipx install
#+end_src

镜像（先别配；真慢再加）：

#+begin_src toml
# ~/.config/uv/uv.toml
[[index]]
url = "https://pypi.tuna.tsinghua.edu.cn/simple"
default = true
#+end_src

PyTorch 轮子的国内镜像（实测可用的只有这两个；清华、BFSU 都是 404）：

#+begin_src shell
https://mirror.sjtu.edu.cn/pytorch-wheels/cu130
https://mirrors.aliyun.com/pytorch-wheels/cu130
#+end_src

*** 现状

已装（2026-10-08）：~uv 0.12.23-1~（pacman，extra）。
再确认：~uv --version~

本仓库的 Python 环境：~code/.venv~（Python 3.14.7，已被 ~.gitignore~ 忽略）。
命令都在 ~code/~ 目录里跑——~uv pip~ 靠当前目录的 ~.venv~ 判断装到哪。

** PyTorch / CUDA

*** 结论

本机能直接跑 GPU 版 PyTorch，用 **Python 3.14** 即可，**不需要**另建 3.12 / 3.13。

*** 为什么

- 显卡 RTX 5080 Laptop，16 GB 显存（sm_120 / Blackwell）；
- 驱动 NVIDIA 615.71.09，支持到 CUDA 13.4；
- 实测 PyTorch **2.14.1 已提供 ~cp314~ 轮子**，官方 ~cu130~ 源里也有 cp314 版本。
  此前担心的「3.14 没轮子」已被推翻（2026-10-08 实测）。

*** 命令

#+begin_src shell
mkdir -p code && cd code
uv venv --python 3.14
uv pip install torch --index-url https://download.pytorch.org/whl/cu130
uv pip install numpy          # torch 轮子不带 numpy，必须补（见下）
#+end_src

~--index-url~ 会把默认源**整个换成** PyTorch 源。实测该源带齐了 torch 的依赖
（sympy / networkx / jinja2 / filelock / fsspec / typing-extensions / setuptools 都装上了），
不必再配 PyPI。

⚠️ 但 **numpy 不是 torch 的依赖**，不会自动装。缺了它 `import torch` 会警告
~Failed to initialize NumPy~，而且 tensor ↔ 数组转换全都用不了。

*** 现状

已装（2026-10-08）：~torch 2.14.1+cu130~，29 个包（含 CUDA 13 运行时 / cuDNN / NCCL / triton，
不需要系统 CUDA）。再确认：

#+begin_src shell
uv run python -c "import torch; print(torch.__version__, torch.cuda.is_available(), torch.cuda.get_device_name(0))"
# 2.14.1+cu130 True NVIDIA GeForce RTX 5080 Laptop GPU
#+end_src
